PREDICT · EVERYONE COMMITS

Before I show you

An LED is connected to a 5 V pin with no resistor. What happens?

A

It lights, dimmer than usual

B

It lights, then burns out

C

Nothing: 5 V is too small

THE ANSWER

click to reveal

THE ANSWER

It lights — and then it burns out.

5 V pushes far more current through an LED than its junction can survive. The resistor is not there to dim it; it is there to set the current to about 15 mA.

Hands up for the one you chose — then we find out.

THE IDEA

A pin is a switch that code controls

HIGH puts 5 V on the pin. LOW puts 0 V on it. Nothing in between.

The same pin, two states. The resistor stays the same in both.

DECODE THE CODE

Six lines, one blinking light

void setup() {

pinMode(13, OUTPUT);

}

void loop() {

digitalWrite(13, HIGH);

delay(500);

digitalWrite(13, LOW);

delay(500);

}

PINMODE(13, OUTPUT)

Faces pin 13 outwards. It will push current, not listen.

DIGITALWRITE(13, HIGH)

Connects pin 13 to 5 V. Current flows, the LED lights.

DELAY(500)

Waits 500 ms — half a second — doing nothing at all.

Type it. Do not copy it.

DEBUG · 5 MINUTES

It does not work. Find the fault.

WHAT YOU SEE

The LED is in the breadboard, the code is uploaded, and nothing lights.

A

The resistor is too big

B

The LED is in backwards

C

delay() is too long

THE FAULT

click to reveal

THE FAULT

The LED is in backwards.

The long leg is the positive one and goes towards the resistor. The short leg goes to GND. Turn it round and it lights — nothing else needs to change.

CHECK · ONE QUESTION

What does digitalWrite(13, HIGH) do to pin 13?

A

Reads the voltage on pin 13

B

Connects pin 13 to 5 V

C

Connects pin 13 to GND

THE ANSWER

click to reveal

ANSWER — B

It connects pin 13 to 5 V.

HIGH is 5 V, LOW is 0 V, and a digital pin can do nothing else. Reading is a different instruction: digitalRead.

If you chose another one, say why. That is the useful bit.
