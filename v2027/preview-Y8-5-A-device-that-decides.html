THE IDEA · THIS ANSWERS THE QUESTION

Two limits, with a gap

Turn the buzzer on when the reading goes below the lower limit. Leave it on until the reading goes above the higher limit. Between the two, do not change anything.

A wobble across one limit turns the buzzer on and off. Two limits, with a gap, stop that.

DECODE THE CODE

A flag, two rules, two outputs

int dry = 0;

void setup() {

pinMode(8, OUTPUT);

pinMode(9, OUTPUT);

Serial.begin(9600);

}

void loop() {

int wetness = analogRead(A0);

if (wetness < 380) dry = 1;

if (wetness > 420) dry = 0;

digitalWrite(8, dry);

digitalWrite(9, dry);

Serial.println(wetness);

delay(200);

}

IF (WETNESS < 380) DRY = 1;

One rule sets the flag. A variable that remembers a decision is a state.

IF (WETNESS > 420) DRY = 0;

A second rule clears it. Between the marks, nothing changes.

DIGITALWRITE(8, DRY)

The flag drives the output. The sensor never drives it directly.

Between 380 and 420, nothing happens.

DEBUG · 5 MINUTES

It does not work. Find the fault.

WHAT YOU SEE

The buzzer is on when the soil is wet, and off when it is dry.

A

The buzzer is wired backwards

B

The comparison is the wrong way round

C

The delay is too long

THE FAULT

click to reveal

THE FAULT

The probe is the other way round in the divider: wet now reads low and dry reads high.

Print the reading in dry soil and in water before writing the rule. With the probe at the top of the divider, dry soil gives a low number, which is why the alarm tests below 380. Swap the probe and the 10 kΩ, or reverse both comparisons.

CHECK · ONE QUESTION

Why two thresholds instead of one?

A

To make the code longer

B

So a reading that wobbles cannot make the buzzer switch on and off

C

Because analogRead is noisy

THE ANSWER

click to reveal

ANSWER — B

So a reading that wobbles cannot make the buzzer switch on and off.

One limit makes the buzzer switch every time the reading wobbles across it. A gap between two limits means it changes only when the reading has really moved.

If you chose another one, say why. That is the useful bit.

STRETCH · IF YOU FINISHED EARLY

If that was easy

THREE STATES

Print DRY, DAMP or WET using two thresholds and an else-if chain. Decide what the buzzer does in each state.

CHOOSE A THRESHOLD FROM DATA

Print the reading with millis() as a timestamp. Leave it running for ten minutes, then find the highest and lowest values. Pick your thresholds from those numbers.

A threshold chosen from data is a design decision. A guessed one is a bug waiting to happen.
